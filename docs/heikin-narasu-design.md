# 平均の導入アプリ「ならして ぴったり！」設計案

作成日：2026-10-24。対象：小学5年生、特別支援学級での個別学習・一斉提示。実装前の設計書。

## 1. 学習の到達点

児童が、操作と自分の言葉・選択で次を確かめられることを目指す。

1. 「ならす」は、多いところから少ないところへ移して、同じ量にすること。
2. ならす前と後で、全部の量は変わらない。
3. 全部を合わせ、もとの個数で等しく分けても、同じ結果になる。
4. その量を「平均」といい、「合計 ÷ 個数」で求められる。

「平均」の名称・公式は最初に提示せず、水差しの操作と式が対応したところで紹介する。平均は、もともとのどれか一つの値と一致するとは限らない。

## 2. 全体の流れ

| 場面 | 児童への問い | 主な操作 | 気付いてほしいこと |
| --- | --- | --- | --- |
| 1 玉 | ならしてみよう！ | 高い棒から低い棒へ玉を移す | 同じ高さにできる |
| 2 土 | たいらな地面にしよう | 高い土を削り、バケットで低い場所へ運ぶ | 減った分が別の場所で増える |
| 3 水 | 同じ量にしよう | 2→3→4→5個のコップ間で水を移す | 数字でも同じ量を確かめられる |
| 4 水差し | まとめてから分けたら？ | 全量を集め、もとの個数へ等分する | 合計と個数を使う方法を発見する |
| 5 式 | 図がなくても分かるかな？ | 合計、個数、平均を順に入力する | 操作を式で表せる |
| 6 練習 | 別の量でもできるかな？ | 図・式・文章の問題を解く | 方法を別の問題に使う |

各場面で「見る→やってみる→確かめる」を基本にする。見本は短く、一つの移動を見せて止まる。長い自動再生を必須にしない。教師は任意の場面に直接移動できる。

## 3. 共通画面と操作

- 上部：現在の場面、短い指示一つ、読み上げボタン。
- 中央：画面の大半を使うSVG。背景の装飾を抑え、動かす物を明確にする。
- 下部：その場面で使う操作、「ひとつ もどす」「はじめの形」「ヒント」、成功後の「つぎへ」。
- 「全部の量」は共通の確認表示とする。導入では折りたたみ、確かめるときに開ける。計算場面では常に参照できる。
- 数字、色、輪郭・模様、位置で意味を伝え、色だけを手掛かりにしない。
- ドラッグと「移す元をタップ→移す先をタップ」を両方用意する。タップだけで全課題を完了できる。
- 実装時は操作対象を原則56 CSS px以上、キーボードのフォーカスも見える大きさにする。選択状態は輪郭と短文で示す。
- 無効な移動は量を変えずに元へ戻す。「ここには おけないよ」など短く伝える。
- 正解までの時間や操作回数で順位を付けない。「大変だった？」は任意の振り返りとし、児童の感想を決め付けない。
- 読み上げは任意。動作中の連打で音声を重ねず、新しい指示に置き換える。音を消しても学習できる。
- 通常／ゆっくり／動きを少なく、停止・再開、見本のやり直しを用意する。
- 教師設定：場面選択、問題選択、数値の編集、ヒント線、数量表示、読み上げ、動きの速さ。学習中の画面には設定を並べすぎない。
- Chromebook横画面では主な教材と操作が一画面に収まることを目標とする。小さい画面では文字や操作領域を縮めすぎず縦配置にする。

## 4. 場面1：棒に通した玉をならす

### 表現

添付写真の道具を真横から見た、1列の4本の棒と台座をSVGで描く。奥行きや隠れた玉をなくし、一つ一つを数えられる配置にする。勝敗や五目並べのルールは入れない。

最初の高さは `[5, 4, 1, 2]`。全部12個、ならすと各3個。棒の最大高さは6個とし、移動先の余裕を残す。玉は同じ大きさ。白・濃色を交互に使う場合も、色は個数や移動可否を意味しない。

### 体験

1. 「ならしてみよう！」と表示。最初から正解の高さは見せない。
2. 棒の一番上の玉を持ち上げ、別の棒に落とすと、その棒の一番上へ吸着する。
3. タップ操作では棒全体を選べる。一番上の玉が選ばれ、「どこへ うつす？」と表示する。
4. 移動中も玉を表示する。途中の玉を抜いて宙に浮く状態は作らない。
5. 全部同じ高さになったら横線が伸び、「どの棒も 3こ。ならせたね！」。
6. 元の形とならした形を並べるか切り替え、「全部で12こ」は同じことを確認する。

ヒントは「高い棒を探す→低い棒を探す→同じ高さの目安線」の順。答えの線は必要なときだけ出す。

追加パターン例：`[4, 2, 3, 3]→3`、`[6, 1, 4, 1]→3`、`[5, 2, 4, 5]→4`。最初は整数個にそろう問題だけを扱う。

## 5. 場面2：土をならす

### 表現

同じ幅・同じ奥行きの区画が横に並ぶ地面の断面図をSVGで描く。区画幅が違うと高さの単純平均が使えないため、教材では幅を統一する。土は細かな同じ面積のブロックで管理し、見た目は土の質感を持つ連続した断面にする。

初回は玉と同じ `[5, 4, 1, 2]` を使い、基準線を高さ3に引く。「線より上の土を、へこんだところへ」。土を捨てたり外から補ったりせず、必ず同じ領域内で移す。

### 重機と操作

ユーザーの意図に合わせたブルドーザー風の車体に、土をためられるバケットを描く。実機の名称・機構を説明する教材にはせず、土の移動を分かりやすく表す。

1. 児童が高い区画を選び「けずる」を押す。
2. 車体が移動し、基準線より上の土の一部を削る。削った部分がそのままバケットへ移る。
3. バケット内の土が見える状態で止まる。児童が低い区画を選び「いれる」を押す。
4. 土がバケットから低い部分へ移り、地面が上がる。
5. 全区画が基準線と一致し、バケットも空になったときだけ完成。

初回のバケット容量は土2単位。一度に移せる量は、削る際は「基準線より上の量」と「バケットの空き」の小さい方、入れる際は「基準線までの不足」と「積んでいる量」の小さい方とする。低い所を削る、高い所に積む、満杯のまま削る操作は実行しない。

削る前・途中・後を通して「地面の土＋バケットの土＋移動中の土＝最初の土」。基準線をまたぐ余剰部分を模様で示し、運んだ後は通常の土に戻す。

「おてほん」は削る→運ぶ→入れるを一手ずつ停止できる。「じぶんで」では移動先を選ぶ。どちらでも同じ保存則を使う。

### パターン

中央が高い、両端が高い、交互に高低、複数の小さな山、一つの大きな山を用意する。まず4区画、慣れたら5〜6区画。最終の高さを先に決め、量を保存して高低差を作る。基準線は任意の固定高さではなく、その問題の総量から計算される高さとする。

## 6. 場面3：コップの水をならす

### 表現と数量

同じ幅、同じ形、同じ容量300mLのまっすぐな透明コップを使う。底の高さ、量に対する高さの倍率、目盛りを統一する。装飾的な先細りコップは使わない。

各コップに「1」「2」などの番号と、現在量を `180 mL` のように常時表示する。水面の高さと数値が同時に変わる。コップの個数が増えても、同じ300mLが同じ高さに見える倍率を守る。

| 段階 | 初期量（mL） | 合計 | ならした量 |
| --- | --- | --- | --- |
| 2個 | 180, 60 | 240 mL | 120 mL |
| 3個 | 180, 60, 120 | 360 mL | 120 mL |
| 4個 | 200, 80, 160, 40 | 480 mL | 120 mL |
| 5個 | 200, 50, 150, 100, 100 | 600 mL | 120 mL |

最初の系列は同じ120mLにそろう問題を使い、個数の変化に集中できるようにする。その後は平均の異なる問題も出し、「いつも120」と覚えることを防ぐ。

### 移動操作

移す元→移す先をタップし、「10 mL うつす」を押す。慣れたら50mLも選べる。ドラッグではコップを重ねた時点で移動先だけを決定し、注ぐボタンで量を確定する。指の細かな位置や押している時間で水量が変わる仕様は避ける。

選べる移動量は問題の数値単位に合わせる。最初の系列は10mL刻み。たとえば平均125mLの発展問題では5mLなどの単位に切り替える。選べる刻みで正解に到達できる問題だけを出す。

水の流れをSVGで表示し、移動途中の数値は「コップ内」「注いでいる量」を含めて総量と一致させる。空の元・満杯の先へは注げない。移動前に実際に移す量を示し、容量や残量を超える要求は実行せず理由を短く示す。

初回は正解線を隠し、ヒントで表示する。「そろったかな？」で確認でき、未完成なら「1ばんが多いね」など比較を助ける。大きな不正解音は使わない。

2→3→4→5個を標準の順序とし、教師は途中を省略できる。5個で行き詰まっても水差しへ進めるようにし、試行錯誤を長時間強制しない。

## 7. 場面4：全部を水差しへ集めて、等しく分ける

### 同じ問題を引き継ぐ

直前のコップの初期量・現在量・個数をそのまま使う。児童が途中までならした場合も、その状態から集める。元の数値カードを画面に残し、途中操作で合計が変わらないことを確認できるようにする。

### 集める

「全部を あわせてみよう」。各コップを順に選ぶと、その水が水差しへ移る。水差しは全量が入る容量とし、容量を表示する。コップと水差しは別の縮尺になる場合があるため、両者の高さを直接比べさせない。

たとえば3個 `[180,60,120]` なら、次の表示を動きに同期させる。

- 1個目：`180 mL`
- 2個目：`180 + 60 = 240 mL`
- 3個目：`180 + 60 + 120 = 360 mL`

すべて集まったら「全部で 360 mL」。空になった3個のコップは消さず、個数の手掛かりとして残す。

### 等しく分ける

「もとの 3このコップに、同じ量ずつ 分けよう」。まず少量ずつ順に配る見本を出し、各コップへ同じ量を配る1巡ごとに止められるようにする。残量を表示し、最後まで配れることを見せる。

続いて「同じ量に分ける」を押すと、同量ずつの配分を完了する。操作と同じ場所に `360 ÷ 3 = 120` を表示し、「1こ分は 120 mL」と確かめる。単に結果へ切り替えず、水差しが減り、各コップが同じ量ずつ増える過程を見せる。

初回は「合計」「コップの数」「1こ分」のカードと、それぞれの図を線で結ぶ。ここで「このように ならした量を、平均といいます」と紹介する。

式の意味を確認する問い：「3で わるのは どうして？」。答えは発話、指差し、または「コップが3こだから」の選択でもよい。

## 8. 場面5：図から式へ

同じ問題のまま、児童の操作で表示を段階的に減らす。

1. 図＋元の量のカード＋式。
2. 小さな図＋元の量のカード＋式。
3. 図を隠し、元の量のカードと式だけ。

最初は「全部でいくつ？」→「何こに分ける？」→「1こ分は？」の入力欄を一つずつ出す。次に `(180 + 60 + 120) ÷ 3 = 120`、最後に `平均 = 合計 ÷ 個数` を対応させる。合計だけで止まった場合は割り算の意味へ、個数を間違えた場合は空のコップの数へ戻る。

「図でたしかめる」は常時利用可能。図を隠せたことを優劣にせず、操作と計算が同じ結果を表すことを確認する。

## 9. 練習問題

最初の1巡は5問。全問、答えた後に図で検証できる。

1. 玉：`[4,2,3]` を移して各3個にする。
2. 水：`[160,80]`、合計240mL、平均120mL。図と数字を併用する。
3. 水：`[60,120,90]`、合計270mL、平均90mL。合計と個数の欄を使う。
4. 式：`[80,160,120,40]`、合計400mL、平均100mL。図は初め隠す。
5. 短い文章：「5このコップに、全部で750mL。ならすと1こ分は？」、答え150mL。

追加問題には0mLの空のコップを含める。例：`[0,120,180]→100mL`。「空でも3このうちの1こ」を図で確かめる。0を個数から除外させない。

導入後の任意発展：`[100,150]→125mL`。水は小分けできることを使い、平均が元のどの数値でもない例にする。玉を半分に割る課題は導入に混ぜない。

誤答では、合計・個数・割り算のどこを確かめるかを示す。ヒントは「多い・少ないに注目→合計に注目→図で一手→全体の見本」の順に深くする。点数のみで終えず、「全部は変わらない」「同じ量に分けられる」の理解も確認する。

## 10. 問題生成の設計

### 玉・土

1. 個数n、ならした高さa、最大高さHを決め、最初は全列をaにする。
2. 異なる2列を選び、一方から他方へ整数k単位を移す。
3. 各列を0〜Hに収めながら複数回繰り返す。玉の初級は最低1個に制限する。
4. 全列同じ、差が大きすぎる、直前と同じ問題を除外する。規定回数で生成できなければ検証済みの固定問題を使う。
5. 最後に合計がn×aであることと、土の余剰量と不足量が一致することを検証する。

土では容量制限付きのバケットで完了できる解手順も生成する。余剰の区画から容量以内を取り、不足の区画へ必要量以内を入れる処理を繰り返す。

### 水

nは2〜5、容量Cは300mL、操作単位uは初級10mL。平均aもuの倍数から選ぶ。全コップaの状態から、uの倍数の水をコップ間で移し、初期値を作る。これにより全量保存、容量内、操作単位で到達可能という条件を満たす。

難しさは個数だけでなく、移動が必要な量、余剰・不足のコップ数でも調整する。合計が同じで配置が違う問題も作り、「形が違っても平均は同じ」を確かめる。

教師の手入力では数値・個数・容量・到達可能性を検証する。整数にそろわない玉や、操作刻みで到達できない水は児童画面へ出さず、教師設定側に修正理由を表示する。

## 11. 実装方針

想定ファイル名：`heikin_narasu.html`。教材の玉・地面・重機・コップ・水差し・水流はSVG、指示・数値入力・ボタンは通常のHTMLで作る。動きは録画動画ではなく、数値に連動するアニメーションとする。

状態を唯一の数値の根拠とする。元の量、現在量、移動中の量、バケット／水差しの量、操作履歴、場面、ヒント段階を保持し、SVGと数値と式を同じ状態から描画する。表示の座標を読み取って答えを計算しない。

移動1回を一つのトランザクションとして扱う。確定前の取消は元へ戻す。動作中の次の移動は受け付けず、停止・再開・元に戻すは使える。場面変更・やり直しでは古いアニメーションと音声を取り消し、遅れて状態を書き換えさせない。

水は整数の最小単位で管理し、浮動小数点の誤差でそろわない状態を防ぐ。完成判定は見た目の近さではなく、全コップの量が一致し、移動中・容器内の残量が条件を満たすことによって行う。

現在の問題と進行位置を端末内に保存し、再開か最初からかを選べる。再開時には移動途中を残さず、最後に完了した操作の状態を使う。個人情報や児童名は保存しない。

## 12. 完成時の確認項目

- 全場面で量が保存される。アニメーション途中の表示も矛盾しない。
- 玉の最上段だけを動かせ、すべて整数個にそろう。
- 土は基準線が総量と一致し、バケット残量0で完成する。容量を超えない。
- 2〜5個すべてで同量の水は同じ高さになり、数値と水位が一致する。
- 水差しは直前の問題を引き継ぎ、合計・個数・平均が同じ操作と対応する。
- 図を隠しても元の数値が残り、いつでも図へ戻れる。
- 空のコップを含む問題でも個数を正しく数える。
- タップのみ、ドラッグ、キーボードそれぞれで操作できる。
- 連打、移動中のやり直し、場面変更、取消、保存再開で量や式が壊れない。
- Chromebook相当の横画面、タブレット、拡大表示で文字と操作が使える。
- 実児童との試行では「どこを触ればよいか」「移った量を追えるか」「等分の意味を言葉や指差しで表せるか」を確認して調整する。設計だけで理解効果を保証しない。
